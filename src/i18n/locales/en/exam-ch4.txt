@@ exam.ydkjs-scope.ch4.2.q
Which of these is a global provided by the hosting environment (the browser) rather than by JS itself?

@@ exam.ydkjs-scope.ch4.2.why
`undefined`, `NaN`, `Math`, `JSON`, `parseInt()` and so on are JS's own built-ins. `console`, the DOM (`window`, `document`), timers and web APIs are globals provided by the environment.

@@ exam.ydkjs-scope.ch4.6.q
On a page whose HTML contains `<li id="first">`, what is the `first` identifier in JS?

A `ReferenceError`, since it isn't declared

@@ exam.ydkjs-scope.ch4.6.o3

@@ exam.ydkjs-scope.ch4.6.why

`window.name` is a pre-defined getter/setter that always turns the value into a string. `var name` doesn't shadow it, it's simply ignored — so `42` becomes the string `"42"`.

@@ exam.ydkjs-scope.ch4.8.q
How is the global object usually referenced in a Web Worker?

@@ exam.ydkjs-scope.ch4.8.why
A worker has no DOM, so there's no `window` alias either. The global object is `self`, and here too only `var`/`function` declarations become its properties.

@@ exam.ydkjs-scope.ch4.10.q

@@ exam.ydkjs-scope.ch4.10.o0
A global variable and a `window` property

@@ exam.ydkjs-scope.ch4.10.o1

@@ exam.ydkjs-scope.ch4.11.q

@@ exam.ydkjs-scope.ch4.11.o0
No, modules are completely isolated from the global scope

@@ exam.ydkjs-scope.ch4.11.o1

@@ exam.ydkjs-scope.ch4.15.q
Why does `(new Function("return this"))()` return the global object?

@@ exam.ydkjs-scope.ch4.15.o0
The `Function()` constructor always runs in strict mode

@@ exam.ydkjs-scope.ch4.15.o1
A function created this way runs in non-strict mode on a normal call, and its `this` points to the global object

@@ exam.ydkjs-scope.ch4.15.o2
The `new` keyword always creates the global object

@@ exam.ydkjs-scope.ch4.15.o3
`Function()` `eval`s the code in the global scope and returns `window`

@@ exam.ydkjs-scope.ch4.15.why
A function built from a string runs in non-strict mode for legacy reasons. On a normal `()` call its `this` is the global object.
