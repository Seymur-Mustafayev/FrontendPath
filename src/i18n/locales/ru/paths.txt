@@ path.web.name
Основы веба — браузер, HTTP и сеть

@@ path.web.sum
Механика, лежащая под фронтендом. Учить React без этого — всё равно что уметь водить машину, не подозревая о существовании двигателя.

@@ path.web.goal
Уметь нарисовать на доске весь путь запроса: от браузера до сервера и обратно, пока он не превратится в пиксели на экране.

@@ path.html.name
HTML — семантическая структура и доступность

@@ path.html.sum
Разметка — это не «куча div». Семантика одновременно решает вопросы SEO, навигации с клавиатуры и экранных дикторов.

@@ path.html.goal
Посмотрев на разметку страницы, уметь сказать, осмысленна ли структура, доступны ли формы и корректны ли метаданные.

@@ path.css.name
CSS — раскладка, адаптивность и современные системы стилей

@@ path.css.sum
Главная борьба в CSS — не выбор цвета, а деление пространства, управление каскадом и то, чтобы ничего не ломалось ни на одном экране.

@@ path.css.goal
Собирать готовый дизайн с помощью токенов и современных инструментов раскладки, без горы media query.

@@ path.js.name
JavaScript — ядро языка и модель выполнения

@@ path.js.sum
Знать React не значит знать JS. На собеседованиях и в реальных багах выручают замыкания, event loop и ссылочная семантика.

@@ path.js.goal
Уметь объяснить, почему код ведёт себя именно так — не «работает», а «почему работает».

@@ path.async.name
Асинхронный JavaScript, работа с HTTP и интеграция API

@@ path.async.sum
Это основная часть реальной фронтенд-работы: получить данные, обработать состояния ожидания и ошибок, правильно настроить аутентификацию.

@@ path.async.goal
Осознанно проектировать все состояния экрана: загрузка, пусто, ошибка, повторная попытка, отмена.

@@ path.ts.name
TypeScript — мышление типами

@@ path.ts.sum
Твой повседневный язык. Разница между junior и middle: использовать типы для моделирования, а не для того, чтобы «заглушить ошибку».

@@ path.ts.goal
Делать невозможные состояния невозможными с помощью типов — не написав ни одного any и ничего не заглушая через as.

@@ path.react.name
React — архитектура компонентов и модель рендеринга

@@ path.react.sum
Твой главный инструмент. Цель здесь — не выучить новые API, а точно знать, когда и почему происходит рендер.

@@ path.react.goal
Уметь объяснить с помощью измерений, почему компонент перерендеривается, и чисто отделять логику от UI.

@@ path.state.name
Управление состоянием — client state и server state

@@ path.state.sum
Вопрос, определяющий уровень middle: кому принадлежат эти данные? Складывать серверные данные в Redux — одна из самых дорогих архитектурных ошибок.

@@ path.state.goal
Выбирать правильное место для каждого фрагмента данных: URL, серверный кэш, глобальный store или локальное состояние.

@@ path.next.name
Next.js и модели рендеринга

@@ path.next.sum
То, где выполняется один и тот же React-код — в браузере, на сервере или во время сборки, — определяет скорость продукта и его SEO.

@@ path.next.goal
Уметь обоснованно выбирать стратегию рендеринга для каждой страницы и управлять поведением кэширования.

@@ path.test.name
Тестирование — Vitest, Testing Library и Playwright

@@ path.test.sum
Твой текущий приоритетный пробел. Middle-разработчик, не умеющий тестировать, не может рефакторить, потому что не знает, что он ломает.

@@ path.test.goal
Не задумываясь знать, какие тесты нужны фиче, и проверять через поведение даже тонкие вещи вроде мемоизации.

@@ path.git.name
Git и CI/CD — процесс в Azure DevOps

@@ path.git.sum
Твой второй приоритетный пробел. Умение писать код неполноценно без знания командного процесса — ошибки здесь затрагивают всю команду.

@@ path.git.goal
Держать историю чистой, без страха разрешать конфликты и самостоятельно выяснять, почему упал pipeline.

@@ path.perf.name
Производительность и Core Web Vitals

@@ path.perf.sum
Чего ждут от middle: превратить жалобу «тормозит» в измерение и указать конкретную причину.

@@ path.perf.goal
Никогда не оптимизировать без измерений; находить настоящее узкое место между бандлом, рендерингом и сетью.

@@ path.tool.name
Инструменты — сборка, линтинг, пакеты и рабочее окружение

@@ path.tool.sum
Невидимый слой, который определяет твою ежедневную скорость. Час, потраченный здесь, каждую неделю возвращает часы.

@@ path.tool.goal
Уметь поднять проект с нуля: сборка, линтинг, форматирование, проверка типов и скрипты.

@@ path.sec.name
Безопасность фронтенда

@@ path.sec.sum
Фронтенд — не последний рубеж безопасности, но первая дверь. На собеседованиях именно эти темы отличают уровень middle.

@@ path.sec.goal
Распознавать риски, связанные с пользовательским контентом, хранением токенов и зависимостями, и выбирать правильную защиту.

@@ path.arch.name
Архитектура, качество кода и переход на уровень middle

@@ path.arch.sum
Этот путь не о технологиях, а о принятии решений. Middle от junior отличает не сам код, а причина выбора.

@@ path.arch.goal
Сохранять растущий проект управляемым и объяснять свои решения на языке компромиссов (trade-offs).
