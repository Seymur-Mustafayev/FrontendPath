@@ topic.web.0.t
Как браузер рендерит страницу

@@ topic.web.0.body
Браузер читает HTML и строит дерево [[dom]], читает CSS и строит [[cssom]]. Вместе они образуют [[render-tree]], после чего идут этапы layout (расчёт размеров и позиций) и paint. Полное название этой последовательности — [[critical-rendering-path]].

Когда меняется ширина, позиция элемента или структура DOM, происходит [[reflow]] — браузер заново выполняет расчёт. Когда меняются только цвет, тень или opacity, срабатывает более дешёвый [[repaint]]. Поэтому в анимациях используют transform и opacity, а не width/top.

Практический вывод: если блокирующий рендер скрипт стоит в head, пользователь смотрит на белый экран. CSS блокирует рендеринг, а JS — парсинг; знать эту разницу — вопрос с собеседования.

@@ topic.web.0.note
Когда это нужно: почему страница медленно открывается, почему заедает прокрутка, почему дёргается анимация — ответ каждый раз находится в этом конвейере.

@@ topic.web.1.t
Протокол HTTP, методы и коды состояния

@@ topic.web.1.body
[[http]] — протокол «запрос–ответ»: метод (GET/POST/PUT/PATCH/DELETE), URL, [[http-header]] и тело. В ответе приходит [[status-code]] — 200 успех, 201 создано, 400 неверные данные, 401 нет аутентификации, 403 нет прав, 404 не найдено, 500 сервер упал.

Путать 401 и 403 — повседневная ошибка: 401 значит «я не знаю, кто ты», 403 — «я знаю, кто ты, но у тебя нет прав». Эта разница требует разного поведения UI: в одном случае отправляем на страницу входа, в другом показываем предупреждение.

[[https]] — это HTTP, зашифрованный поверх [[tls]]; в продакшене другого варианта нет.

@@ topic.web.2.t
DNS, домен, хостинг и CDN

@@ topic.web.2.body
Когда вводится адрес, первым делом выполняется запрос [[dns]] — доменное имя превращается в IP. Затем запрос попадает на сервер в среде [[hosting]]. Статические файлы (JS, CSS, изображения) обычно отдаются через [[cdn]], чтобы пользователь получал их из ближайшей точки.

Это знание пригождается при деплое: если сайт изменился, а выглядит по-старому, причина часто в кэше CDN, а не в твоём коде.

@@ topic.web.3.t
Модель клиент–сервер и чтение REST API

@@ topic.web.3.body
В модели [[client-server]] фронтенд — это клиент: отправляет запрос, получает ответ в [[json]] и показывает его. В стиле [[rest]] каждый ресурс представлен [[endpoint]]: GET /orders — список, GET /orders/12 — один элемент, POST /orders — создание.

Главный навык на уровне junior: прочитать документацию Swagger/Postman, правильно собрать запрос, понять форму ответа и превратить его в модель, удобную для UI.

@@ topic.web.4.t
Поиск проблем с помощью DevTools

@@ topic.web.4.body
[[devtools]] — твой основной инструмент диагностики. Во вкладке [[network-tab]] видны статус, payload и ответ каждого запроса — большинство проблем «данные не приходят» проявляются здесь как 401, CORS или неверный URL.

Поставить [[breakpoint]] в панели Sources и выполнять код пошагово в разы быстрее, чем куча console.log. А в панели Elements видно, какое CSS-правило победило и какие зачёркнуты.

@@ topic.web.4.note
Привычка: любой баг начинай с Network, потом Console, потом код. Обратный порядок — потеря времени.

@@ topic.html.0.t
Семантические теги и структура документа

@@ topic.html.0.body
[[semantic-html]] означает, что имя элемента выражает смысл содержимого: header, nav, main, article, section, footer. Они же играют роль [[landmark]], и экранный диктор навигирует по ним.

Иерархия заголовков (h1 → h2 → h3) должна идти по порядку; правильный подход — выбирать заголовок по уровню, а не по размеру, а размер задавать через CSS. Если на что-то нажимают, это должен быть button; если это переход — a. Повесить onClick на div — значит оставить пользователя клавиатуры за бортом.

@@ topic.html.1.t
Формы, типы input и валидация

@@ topic.html.1.body
Элемент формы должен быть связан с label (for/id) — иначе [[screen-reader]] не поймёт, что это за поле. Если правильно выбрать [[input-type]], мобильная клавиатура и проверка браузером достаются бесплатно.

Собственные атрибуты [[form-validation]] в HTML (required, min, pattern) — первая линия защиты, но не последнее слово: сервер тоже должен проверять данные. Для отправки файлов и смешанных данных самый простой путь — [[formdata]].

@@ topic.html.2.t
Доступность (a11y) — практический минимум

@@ topic.html.2.body
На уровне middle [[a11y]] — не «дополнение», а требование. Минимальный набор: каждый интерактивный элемент достижим с клавиатуры, [[tab-order]] логичен, фокус виден, контраст достаточен.

Атрибуты [[aria]] добавляют смысл там, где семантики не хватает (кастомный dropdown, модальное окно, вкладки). Золотое правило: если есть подходящий семантический тег, не пиши ARIA — неправильный ARIA хуже, чем его отсутствие. При открытии модального окна займись [[focus-management]]: перенеси фокус внутрь, закрывай по Escape, при закрытии верни фокус на кнопку, которая его открыла.

@@ topic.html.2.note
Это важно и во внутренних системах вроде AIPOS: оператор весь день работает с клавиатуры и не хочет тянуться к мыши.

@@ topic.html.3.t
Мета-теги, SEO и карточки для шеринга

@@ topic.html.3.body
Набор [[meta-tag]] рассказывает браузеру и поисковику о странице: title, description, viewport, canonical. Для [[seo]] структура (заголовки, семантические теги, скорость) начинается с разметки.

Картинка и заголовок, которые видны, когда ссылкой делятся, управляются тегами [[open-graph]]. В Next.js они задаются через metadata API.

@@ topic.html.4.t
Изображения, медиа и стратегия загрузки

@@ topic.html.4.body
Всегда задавай изображениям width/height или aspect-ratio — иначе при загрузке страница прыгает и [[cls]] ухудшается. Для изображений ниже первого экрана используй [[lazy-loading]], для разных экранов — [[srcset]].

Выбор формата — самый дешёвый выигрыш: [[webp]] даёт то же качество при заметно меньшем размере и напрямую улучшает метрику [[lcp]].

@@ topic.css.0.t
Box model, специфичность и каскад

@@ topic.css.0.body
Каждый элемент — это [[box-model]]: content, padding, border, margin. box-sizing: border-box упрощает расчёт размеров и является стандартной практикой.

Какое правило сработает, определяют [[specificity]] и [[cascade]]. !important почти всегда признак того, что структура неправильная, — вместо него упрости селектор или используй [[cascade-layer]]. Некоторые свойства переходят от родителя к потомку через [[inheritance]], некоторые нет: font наследуется, padding — нет.

@@ topic.css.1.t
Flexbox — выравнивание по одной оси

@@ topic.css.1.body
[[flexbox]] располагает элементы вдоль одной оси. Ключ — понять [[main-axis]]: когда меняется flex-direction, роли justify-content и align-items тоже меняются местами.

[[flex-grow]], flex-shrink и flex-basis определяют, как распределяется свободное пространство. Тулбары, группы кнопок, строки внутри карточки — это работа для flexbox.

@@ topic.css.2.t
CSS Grid — раскладка по двум осям

@@ topic.css.2.body
[[css-grid]] предназначен для структуры страницы. Колонки задаются через [[grid-template]], а [[fr-unit]] распределяет оставшееся место.

Кратчайший путь к адаптивной сетке карточек: repeat(auto-fill, minmax(240px, 1fr)) — число колонок подстраивается само, без единого media query. Правило: структура страницы и разделов — Grid, строки внутри компонента — Flex.

@@ topic.css.3.t
Адаптивный дизайн и подход mobile-first

@@ topic.css.3.body
В [[responsive]] дизайне подход [[mobile-first]] означает меньше кода: собери базу для узкого экрана, а затем расширяй её через [[media-query]] с min-width.

Значения [[breakpoint-css]] выбирай не по названиям устройств, а по ширине, на которой дизайн действительно ломается. Если использовать [[clamp]] для шрифтов и отступов, страница остаётся аккуратной и на промежуточных размерах.

@@ topic.css.3.note
Привычка при проверке: сузь ширину в DevTools до 360px — если появилась горизонтальная прокрутка, раскладка неверна.

@@ topic.css.4.t
Современный CSS: переменные, container query, :has()

@@ topic.css.4.body
С помощью [[css-variable]] создаются токены цветов, отступов и радиусов; смена темы сводится к переопределению нескольких переменных.

[[container-query]] позволяет компоненту реагировать на ширину собственного контейнера — одна и та же карточка может выглядеть по-разному в сайдбаре и в широкой области. [[has-selector]] выбирает родителя по его потомкам и решает в CSS задачи, которые раньше требовали JS. В больших кодовых базах [[cascade-layer]] прекращает войну приоритетов.

@@ topic.css.5.t
Tailwind CSS и подход utility-first

@@ topic.css.5.body
[[tailwind]] работает с готовыми атомарными классами. Сила подхода [[utility-first]] — скорость и отсутствие необходимости придумывать имена; слабость — длинные повторяющиеся строки классов. Решение — превращать повторяющийся блок в компонент, а не в гору @apply.

Конфигурация Tailwind — это, по сути, твой набор [[design-token]]. Если используешь его вместе с готовой UI-библиотекой вроде DevExtreme, держи границу чёткой: вмешиваться во внутренние стили компонента библиотеки через утилиты — не долговечное решение.

@@ topic.css.6.t
Переходы, анимация и уважение к настройкам движения

@@ topic.css.6.body
[[transition]] — для изменения одного свойства, [[keyframes]] — для многоэтапной анимации. Ради производительности анимируй только transform и opacity — всё остальное вызывает [[reflow]].

Уважай запрос [[prefers-reduced-motion]]: если пользователь отключил анимации в системе, твоя страница тоже должна быть спокойной.

@@ topic.js.0.t
Scope, hoisting, замыкания и TDZ

@@ topic.js.0.body
[[scope]] — область видимости переменной; let/const имеют блочную область, var — функциональную. [[hoisting]] поднимает объявления в начало области, но let/const остаются в [[tdz]] и при обращении выбрасывают ошибку.

[[closure]] — это когда функция запоминает окружение, в котором была создана. Самое известное следствие в React — stale closure: внутри setInterval или старого колбэка «застревает» устаревшее значение состояния. Решение — функциональное обновление (setN(n => n+1)) или правильно указанные зависимости.

@@ topic.js.0.note
Эта тема лежит в корне багов useEffect и useCallback; если она не усвоена, оптимизация React превращается в гадание.

@@ topic.js.1.t
this, цепочка прототипов и классы

@@ topic.js.1.body
[[this]] зависит от того, как функция вызвана, а не от того, где она написана; исключение — стрелочные функции, в них this лексический. Семейство [[bind]] (call/apply/bind) задаёт this явно.

Наследование в JS работает через цепочку [[prototype]]; синтаксис [[class]] — читаемая оболочка поверх неё. Даже если в функциональном мире React это не нужно каждый день, это нужно для старого кода, внутренностей библиотек и собеседований.

@@ topic.js.2.t
Операции с массивами/объектами и иммутабельность

@@ topic.js.2.body
Тройка [[map-filter-reduce]] — основа обработки данных во фронтенде: преобразовать, отфильтровать, агрегировать. [[destructuring]] и [[spread]] сокращают код и, главное, упрощают соблюдение правила [[immutability]].

Прямое изменение состояния React (push, запись в поле объекта) не вызывает ре-рендер, потому что сравнение идёт по ссылке. Поэтому всегда возвращай новый массив или объект. Для глубоких объектов помогают structuredClone или Immer.

@@ topic.js.3.t
Event loop, call stack и очередь микрозадач

@@ topic.js.3.body
JS однопоточен: выполнение идёт через [[call-stack]]. Когда асинхронная работа завершается, колбэк попадает в очередь, и [[event-loop]] забирает его, как только стек опустеет.

Главный нюанс: очередь [[microtask]] (Promise) опустошается раньше, чем [[task-queue]] (setTimeout). Поэтому Promise.resolve().then(...) выполняется раньше, чем setTimeout(..., 0). Долгое синхронное вычисление блокирует стек, и UI зависает — это прямая причина ухудшения метрики [[inp]].

@@ topic.js.4.t
ES-модули, import/export и tree shaking

@@ topic.js.4.body
[[esm]] имеет статическую структуру — бандлер ещё при сборке знает, кто что использует, и выбрасывает лишний код с помощью [[tree-shaking]].

Команде стоит выбрать один стиль между [[named-export]] и default export; именованный экспорт предсказуемее при рефакторинге и автоимпорте. Для условной загрузки тяжёлых библиотек есть [[dynamic-import]].
