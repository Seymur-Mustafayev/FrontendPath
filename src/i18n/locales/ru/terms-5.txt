@@ term.syntax-error.tr
Синтаксическая ошибка

@@ term.syntax-error.def
Код не соответствует грамматическим правилам. Важное наблюдение: даже если ошибка в третьей строке, `console.log` в первой строке НЕ ВЫПОЛНЯЕТСЯ.

```js
var greeting = 'Hello';
console.log(greeting);
greeting = .'Hi';
// SyntaxError: unexpected token .
// «Hello» НЕ выводится
```

Это прямое доказательство того, что движок парсит всю программу до выполнения.

@@ term.early-error.tr
Ранняя ошибка

@@ term.early-error.def
Ошибка, которая синтаксически корректна, но которую спецификация требует выбросить до выполнения.

```js
console.log('Howdy');
saySomething('Hello','Hi');
// SyntaxError: Duplicate parameter name not allowed

function saySomething(greeting,greeting) {
  'use strict';
  console.log(greeting);
}
```

«Howdy» не печатается. Обрати внимание: прагма `'use strict'` написана ВНУТРИ функции, ПОСЛЕ параметров, — значит, когда движок проверяет параметры, он уже прочитал всю функцию. Это второе доказательство модели [[two-phases]] ([[js-strict-mode]]).

@@ term.js-strict-mode.tr
Строгий режим JS

@@ term.js-strict-mode.def
Более безопасное подмножество JS. Включается через `'use strict'` в начале файла или функции; в ES-модулях и классах активен автоматически.

Что он запрещает: случайное создание глобальных переменных, повторяющиеся имена параметров, [[with-statement]], изменение области видимости через [[eval]] и многое другое.

В современном коде этот режим практически всегда включён — поэтому многие «трюки» из книги уже невозможны.

@@ term.hoisting_book.tr
Поднятие

@@ term.hoisting_book.def
Регистрация объявлений в области видимости до выполнения. Книга приводит это как третье доказательство модели [[two-phases]]:

```js
function saySomething() {
  var greeting = 'Hello';
  {
    greeting = 'Howdy';   // ошибка возникает ЗДЕСЬ
    let greeting = 'Hi';
    console.log(greeting);
  }
}
saySomething();
// ReferenceError: Cannot access 'greeting' before initialization
```

На строке `greeting = 'Howdy'` движок уже знает, что это имя относится к `let greeting` с блочной областью на СЛЕДУЮЩЕЙ строке. Это можно знать, только если заранее обработать код и построить области видимости.

> Предупреждение книги: утверждение «let/const не поднимаются» неверно — они тоже поднимаются, просто остаются внутри [[tdz]].

@@ term.target-source.tr
Цель и источник

@@ term.target-source.def
Помимо объявлений, каждое обращение к переменной в программе играет одну из двух ролей: если в неё записывается значение — это target (LHS), если её значение читается — source (RHS).

```js
students = [ /* ... */ ];        // target
for (let student of students)     // student: target, students: source
getStudentName(73)                // 73 записывается в параметр studentID: target
function getStudentName(id) {}    // объявление функции: особый случай target
console.log(nextStudent)          // console и nextStudent: source
```

Почему это важно: когда поиск неудачен, результат зависит от роли. В строгом режиме и ненайденный target, и ненайденный source дают ReferenceError; в нестрогом режиме ненайденный target может случайно создать глобальную переменную.

@@ term.function-hoisting.tr
Поднятие функций

@@ term.function-hoisting.def
В объявлении функции связь между именем и значением-функцией устанавливается во время компиляции, в САМОМ НАЧАЛЕ области видимости, — присваивания через `=` она не ждёт.

```js
greet();   // работает
function greet(){ console.log('привет'); }

greet2();  // TypeError: greet2 is not a function
var greet2 = function(){};   // поднимается только `greet2`, а не значение
```

Поэтому разница между объявлением `function` и функциональным выражением (expression) — это реальная разница в поведении, а не вопрос стиля.

@@ term.eval.tr
Выполнение строки как кода

@@ term.eval.def
Компилирует и выполняет код, переданный строкой, во время работы программы. Если в нём есть объявление `var` или `function`, он ИЗМЕНЯЕТ текущую область видимости:

```js
function badIdea() {
  eval("var oops = 'Ugh!';");
  console.log(oops);   // Ugh!
}
```

Почему это плохо: уже скомпилированная и оптимизированная область видимости перестраивается при каждом вызове (производительность), код становится нечитаемым, а в сочетании с пользовательскими данными появляется уязвимость прямого выполнения кода (того же семейства, что и [[xss]]).

В строгом режиме объявления не влияют на вызывающую область видимости.

@@ term.with-statement.tr
Блок with

@@ term.with-statement.def
Превращает объект в локальную область видимости во время выполнения — его свойства видны в этом блоке как переменные:

```js
var badIdea = { oops: 'Ugh!' };
with (badIdea) {
  console.log(oops);   // Ugh!
}
```

Глобальная область здесь не меняется, но объект `badIdea` становится областью видимости во время выполнения, а не во время компиляции. Это вредно для производительности и читаемости и полностью запрещено в строгом режиме.

@@ term.lexical-scope.tr
Лексическая область видимости

@@ term.lexical-scope.def
Модель областей видимости в JS: где видна переменная, целиком определяется РАСПОЛОЖЕНИЕМ В КОДЕ функций, блоков и объявлений, а не тем, где функция вызывается.

Слово «lexical» происходит от названия этапа компиляции [[tokenizing]].

Правила: `var` привязывается к ближайшей функции, `let`/`const` — к ближайшему блоку `{ }` ([[function-scope]], [[block-scope]]). В этом главное отличие от языков с динамической областью видимости (например, некоторых shell-языков).

@@ term.block-scope.tr
Блочная область видимости

@@ term.block-scope.def
Переменная, объявленная через `let` и `const`, принадлежит ближайшему блоку `{ .. }`: `if`, `for` или просто отдельному блоку.

```js
if (true) {
  let a = 1;
  var b = 2;
}
console.log(b);   // 2
console.log(a);   // ReferenceError
```

Практический вывод: в циклах `let` создаёт новую привязку на каждой итерации — это решение классического примера с `setTimeout` из темы [[closure]].

@@ term.function-scope.tr
Функциональная область видимости

@@ term.function-scope.def
Переменная, объявленная через `var`, принадлежит ближайшей функции независимо от блоков. Поэтому `var`, объявленный внутри `if` или `for`, виден и за пределами блока.

Это поведение не ошибка, а просто старая модель; в современном коде выбор по умолчанию — `const`, а при необходимости — `let`.

@@ term.scope-chain.tr
Цепочка областей видимости

@@ term.scope-chain.def
Если переменная не найдена в текущей области, движок смотрит на уровень выше — в охватывающую область. Процесс продолжается, пока не найдётся подходящее объявление или пока не будет достигнута глобальная область.

Если переменная нигде не найдена, она считается «undeclared» ([[undeclared]]).

Цепочка строится во время компиляции, то есть ещё до выполнения известно, какая переменная к какой области относится.

@@ term.undeclared.tr
Необъявленная и неопределённая

@@ term.undeclared.def
Два совершенно разных случая:

```js
let a;
console.log(a);      // undefined — переменная есть, значения нет
console.log(b);      // ReferenceError: b is not defined — такой переменной НЕТ
```

«Undeclared» означает, что переменная не найдена ни в одной лексической области. В нестрогом режиме ненайденная target-ссылка случайно создаёт глобальную переменную — одно из самых вредных поведений, которые запрещает строгий режим.

@@ term.lexical-environment.tr
Лексическое окружение

@@ term.lexical-environment.def
Реальное воплощение области видимости во время выполнения. Компиляция строит только ПЛАН — определяет, какие будут области и где будет зарегистрирован каждый идентификатор; память не выделяется.

Сами области создаются только во время выполнения, каждый раз, когда эта область запускается. Поэтому два вызова одной функции создают два отдельных окружения — именно на этом основано [[closure]].

@@ term.first-class-function.tr
Функция первого класса

@@ term.first-class-function.def
Функции в JS — обычные значения: их можно записать в переменную, передать как аргумент, вернуть из другой функции.

```js
const run = (fn) => fn();
const make = () => () => 'привет';
```

Когда это свойство сочетается с [[closure]], становится возможной вся модель хуков React: функция несёт с собой окружение, в котором была создана, и может быть вызвана позже в любом месте.

@@ term.module-pattern.tr
Паттерн «модуль»

@@ term.module-pattern.def
Способ организации кода, который хранит скрытые переменные во внутренней области видимости и выдаёт наружу только выбранные функции. Механизм, обеспечивающий приватность, — [[closure]].

```js
function createCounter(){
  let count = 0;                 // недоступно снаружи
  return {
    inc: () => ++count,
    get: () => count
  };
}
```

Современные модули [[esm]] — форма той же идеи на уровне языка: всё, что не экспортировано, остаётся внутри модуля.

@@ term.identifier.tr
Идентификатор

@@ term.identifier.def
Имя переменной, функции, класса или параметра. Замечание книги: в выражениях `student.id`, `student.name` и `console.log` слова `id`, `name`, `log` — не идентификаторы, а имена СВОЙСТВ (property).

Разница важна: правила областей видимости относятся только к идентификаторам, а поиск свойств идёт по цепочке [[prototype]].

document.querySelector('#app').textContent = 'Привет'
