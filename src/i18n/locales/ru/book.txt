@@ sec.ydkjs-scope.ch1.intro.note
Глава начинается с вопроса: откуда JS знает, какая переменная видна из какой строки?

Ответ в том, что эти правила не случайны — они применяются ДО ТОГО, как программа начнёт ВЫПОЛНЯТЬСЯ.

@@ sec.ydkjs-scope.ch1.about.heading
Об этой книге

@@ sec.ydkjs-scope.ch1.about.note
Здесь объявляются три ключевых понятия книги:

1. **Scope** — правила видимости переменных, определяются во время компиляции.
2. **Closure** — поскольку функция является значением первого класса, её можно передать куда угодно, но она несёт с собой окружение, в котором была создана.
3. **Module** — структура, которая благодаря замыканию скрывает внутренние переменные и открывает только выбранные функции.

Обрати внимание: фраза «структура областей видимости не зависит от условий выполнения» задаёт ось всей книги — какие переменные увидит функция, зависит от того, ГДЕ ОНА НАПИСАНА, а не от того, где вызвана.

Этот раздел — ядро главы. Для собеседования: правильный ответ на вопрос «разве let и const не поднимаются?» — **поднимаются**, просто из-за [[tdz]] обращение к ним до объявления выбрасывает ReferenceError. А `var` поднимается и инициализируется значением `undefined`.

@@ sec.ydkjs-scope.ch1.compiler-speak.heading
Язык компилятора

@@ sec.ydkjs-scope.ch1.compiler-speak.note
Почему это важно: когда поиск неудачен, результат зависит от роли.

```js
// не найден source:
console.log(notDefined);   // ReferenceError — в любом режиме
// не найден target:
function f(){ oops = 5; }  // нестрогий режим: создаёт ГЛОБАЛЬНУЮ переменную (!)
f();                        // в строгом режиме: ReferenceError
```

Это одна из самых ценных защит строгого режима: случайно созданная глобальная переменная — один из самых трудно находимых багов в реальном проекте.

@@ sec.ydkjs-scope.ch1.cheating.heading
Жульничество: изменение scope во время выполнения

@@ sec.ydkjs-scope.ch1.cheating.note
`eval` — не просто проблема производительности: в сочетании с пользовательскими данными он создаёт уязвимость прямого выполнения кода. Другие формы того же семейства: `new Function(str)`, `setTimeout("код", 0)`.

Практическое правило во фронтенде: ни одна строка из внешнего источника не должна выполняться как код — ни через `eval`, ни через `innerHTML` (смотри тему [[xss]]).

@@ sec.ydkjs-scope.ch1.lexical-scope.heading
Лексическая область видимости

@@ sec.ydkjs-scope.ch1.lexical-scope.note
Самый тонкий момент — в последнем предложении: компиляция строит лишь КАРТУ, а области видимости создаются заново при каждом вызове.

Это одно предложение — ключ к понятию [[closure]]: каждый вызов создаёт своё окружение, а функция несёт это окружение с собой. Отсюда же проблема stale closure в React: каждый рендер создаёт свой набор переменных.
