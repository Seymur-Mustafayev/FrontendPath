@@ term.scope-manager.tr
Менеджер областей видимости

@@ term.scope-manager.def
Метафора из главы 2 книги: у каждого scope есть свой «менеджер», который хранит список идентификаторов, объявленных в этом scope.

Компилятор спрашивает его «слышал ли ты об этом имени?», и при необходимости регистрируется новая переменная. Во время выполнения движок просит его найти переменную; если она не найдена, вопрос передаётся менеджеру на уровень выше ([[scope-chain]]).

@@ term.accidental-global.tr
Случайная глобальная переменная

@@ term.accidental-global.def
В нестрогом режиме присваивание значения переменной, которая нигде не объявлена, молча создаёт глобальную переменную.

```js
function save() {
  total = 100;   // нет let/const/var
}
save();
console.log(total);   // 100 — стала глобальной!
```

В [[js-strict-mode]] (и в ES-модулях) это приводит к `ReferenceError` — лучшая защита от случайных глобальных переменных.

@@ term.shadowing.tr
Затенение

@@ term.shadowing.def
Когда во внутреннем scope объявляется переменная с тем же именем, что и во внешнем, внутренняя «затеняет» внешнюю: начиная с этой точки и глубже, к внешней переменной нельзя обратиться по имени.

```js
const name = 'Kyle';
function greet(name) {   // параметр затеняет внешний name
  return name;
}
greet('Suzy');   // Suzy
```

Правило ESLint `no-shadow` ловит случайное затенение.

@@ term.global-scope.tr
Глобальная область видимости

@@ term.global-scope.def
Самая внешняя область — последняя остановка цепочки scope. Здесь живут встроенные сущности JS (`Math`, `JSON`, `Promise`) и API среды (`window`, `document`, `setTimeout`).

В обычном файле `<script>` `var`/`function` верхнего уровня становятся глобальными. А в ES-модулях и Node верхний уровень файла — не глобальный, а scope модуля. Загрязнение глобального scope ведёт к конфликтам имён, поэтому современный код использует модули.

@@ term.global-object.tr
Глобальный объект

@@ term.global-object.def
Объектное представление глобального scope. Его имя зависит от среды: `window` в браузере, `self` в Web Worker, `global` в Node и [[globalthis]] везде.

Только объявления `var` и `function` отражаются как свойства глобального объекта; `let`, `const` и `class` — нет:

```js
var a = 1;  let b = 2;
window.a;   // 1
window.b;   // undefined
```

@@ term.globalthis.tr
globalThis

@@ term.globalthis.def
Стандартная ссылка на глобальный объект, добавленная в ES2020 и работающая во всех средах (браузер, Node, Web Worker). Позволяет писать универсальный код, не думая о различиях между `window`, `self` и `global`.

```js
if (typeof globalThis.fetch !== 'function') {
  // старая среда — загрузить полифил
}
```

@@ term.named-function-expression.tr
Именованное функциональное выражение

@@ term.named-function-expression.def
Функция, используемая как значение, но со своим именем: `const f = function helper() {}`.

Имя (`helper`) не попадает во внешний scope — оно видно только внутри самой функции и доступно только для чтения. Польза: имя видно в stack trace, функция может рекурсивно вызывать себя. Версия без имени называется «анонимным функциональным выражением».

@@ term.arrow-function.tr
Стрелочная функция

@@ term.arrow-function.def
Краткий синтаксис функционального выражения, появившийся в ES6: `(a, b) => a + b`.

С точки зрения scope ведёт себя как обычная функция — создаёт собственную область. Настоящие отличия:

- нет собственного [[this]], берётся внешний `this`;
- нет собственного `arguments`;
- нельзя вызвать через `new`;
- лексически анонимна (имя лишь выводится из переменной).

@@ term.web-worker.tr
Web Worker

@@ term.web-worker.def
Возможность браузера запускать JS-файл в фоновом потоке, отдельно от основного. Используется, чтобы тяжёлые вычисления не замораживали интерфейс.

У воркера собственный глобальный scope (`self`) и нет доступа к DOM. Связь с основным потоком — только через `postMessage` и `onmessage`.

```js
const worker = new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' });
worker.postMessage(bigData);
```

@@ term.commonjs.tr
Модули CommonJS

@@ term.commonjs.def
Изначальный формат модулей Node: импорт через `require()`, экспорт через `module.exports`. Каждый файл — отдельный модуль, ведущий себя как singleton.

```js
const { getName } = require('./student.js');
module.exports.getName = getName;
```

В отличие от [[esm]], он динамичен (работает во время выполнения), поэтому бандлер не может выбросить неиспользуемые части ([[tree-shaking]] работает слабо).

@@ term.redeclaration.tr
Повторное объявление

@@ term.redeclaration.def
Попытка объявить ту же переменную в одном scope второй раз.

- С `var`: разрешено, но ничего не делает (no-op) — значение не сбрасывается.
- Если участвует `let`/`const`: `SyntaxError` — «has already been declared».

```js
var a = 1;
var a;          // a всё ещё 1
let b = 1;
let b = 2;      // SyntaxError
```

Поскольку каждая итерация цикла — новый экземпляр scope, `let` внутри цикла не считается повторным объявлением.

@@ term.pole.tr
Принцип наименьшей открытости

@@ term.pole.def
Объявляй каждую переменную и функцию в наименьшем scope, достаточном для её работы; всё остальное держи скрытым.

Защищает от трёх опасностей: **конфликтов имён**, **неожиданного поведения** (кто-то другой меняет твои скрытые данные) и **нежелательной зависимости** (чужой код зависит от твоих внутренних деталей и усложняет рефакторинг).

Во фронтенде: компонент не открывает внутренний state как props, модуль делает `export` только нужного.

@@ term.iife.tr
Немедленно вызываемое функциональное выражение

@@ term.iife.def
Функциональное выражение, вызываемое в момент определения. Создаёт отдельный scope для скрытия переменных.

```js
const counter = (function () {
  let count = 0;             // снаружи не видно
  return () => ++count;
})();
```

До ES-модулей это был главный способ создать «модуль». Сегодня чаще всего встречается для вызова async-функции внутри `useEffect`. Внимание: IIFE — граница функции, поэтому меняет смысл `return`, `this`, `break` и `continue`.

@@ term.memoization.tr
Мемоизация

@@ term.memoization.def
Кэширование результата функции по входным данным: при повторе того же входа вычисление не повторяется, результат берётся из кэша. Кэш обычно скрыт в [[closure]].

```js
const square = (() => {
  const cache = {};
  return (n) => cache[n] ?? (cache[n] = n * n);
})();
```

В React `useMemo`, `useCallback` и `React.memo` — применения той же идеи. Это обмен памяти на скорость — следи за размером кэша.

@@ term.fib.tr
Объявления функций в блоках

@@ term.fib.def
Объявление `function name() {}` внутри блока `if`, `for` или явного `{ }`. По спецификации у него блочный scope, но ради совместимости с унаследованным поведением браузерные движки (и Node) работают иначе — результат зависит от среды.

Правило: не пиши **объявление** функции внутри блока. Если нужна условная функция, используй функциональное **выражение**:

```js
const format = isMobile ? shortFormat : longFormat;
```

@@ term.gc.tr
Сборка мусора

@@ term.gc.def
Автоматическое освобождение JS-движком памяти значений, на которые больше нигде нет ссылок.

Если переменная всё ещё удерживается каким-либо [[closure]], она не собирается. Поэтому неудалённые обработчики событий, интервалы и подписки вызывают [[memory-leak]]. В React функция очистки `useEffect` существует именно для того, чтобы разрывать эти ссылки.

@@ term.callback.tr
Функция обратного вызова

@@ term.callback.def
Функция, передаваемая в другую функцию как аргумент и вызываемая позже — сразу (`map`, `find`) или в будущем (`setTimeout`, `addEventListener`, `then`).

Колбэки — самая частая форма [[closure]]: колбэк видит переменные scope, в котором был создан, даже когда тот давно завершился.

```js
function load(id) {
  fetch(`/api/${id}`).then((res) => console.log(id, res.status));
}
```

@@ term.partial-application.tr
Частичное применение

@@ term.partial-application.def
Передача части аргументов функции с несколькими параметрами заранее и получение новой функции, ожидающей остальные. Заранее переданные аргументы хранятся в [[closure]]. Близкий родственник — **каррирование** (цепочка функций, принимающих аргументы по одному).

```js
const handleChange = (field) => (e) =>
  setForm((f) => ({ ...f, [field]: e.target.value }));
```

@@ term.encapsulation.tr
Инкапсуляция

@@ term.encapsulation.def
Объединение данных и поведения, служащих одной цели, и скрытие внутренних деталей от внешнего мира.

У неё две стороны: **группировка** (связанное лежит вместе — например, в одном файле компонента) и **контроль видимости** (открыт только публичный API). В JS приватность обеспечивается в основном лексическим scope и [[closure]], а также полями `#private` у `class`.

@@ term.namespace-object.tr
Пространство имён

@@ term.namespace-object.def
Группировка связанных, но не хранящих состояние функций под одним объектом: `Utils.wait()`, `Utils.isValidEmail()`.

Это не модуль: нет ни скрытого состояния, ни скрытых деталей. В ESM `import * as Utils from './utils'` тоже создаёт объект пространства имён. Это не плохо — просто не называй его модулем.

@@ term.module-factory.tr
Фабрика модулей

@@ term.module-factory.def
Обычная функция, которая при каждом вызове возвращает **новый, независимый** экземпляр модуля (со своим скрытым состоянием). В отличие от [[singleton]], созданного через IIFE, экземпляров можно создать сколько угодно.

```js
function createStore(initial) {
  let state = initial;
  return { get: () => state, set: (v) => { state = v; } };
}
const a = createStore(0);
const b = createStore(10);   // отдельное состояние
```

Кастомные хуки — тоже фабрики, создающие отдельное состояние для каждого компонента.

@@ term.singleton.tr
Singleton (одиночка)

@@ term.singleton.def
Модуль или объект, у которого на всю программу только один экземпляр. Классический модуль через IIFE, модуль CommonJS и ES-модуль — все являются singleton: сколько бы раз ты ни импортировал файл, получаешь тот же экземпляр.

Типичные singleton во фронтенде: API-клиент, глобальный store (Zustand, Redux), экземпляр i18n. Внимание: состояние singleton общее для всего приложения — между тестами его нужно сбрасывать.
