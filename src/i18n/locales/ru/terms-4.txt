@@ term.engine.tr
Движок JavaScript

@@ term.engine.def
Программа, которая обрабатывает и выполняет твой код: V8 (Chrome, Node.js), SpiderMonkey (Firefox), JavaScriptCore (Safari).

Движок не просто читает код строка за строкой — сначала он его парсит, превращает во внутреннее представление (байткод), затем выполняет и во время выполнения заново оптимизирует горячие (часто выполняемые) части.

Главное утверждение книги: без знания этой модели обработки невозможно объяснить правила [[scope]].

@@ term.engine.ex
V8 → parse → AST → bytecode (Ignition) → оптимизированный код (TurboFan)

@@ term.compilation.tr
Компиляция

@@ term.compilation.def
Преобразование всего исходного кода в список инструкций, понятных машине. Результат обычно сохраняется в файл и затем выполняется.

В JavaScript этот процесс происходит не на шаге сборки, а за несколько микросекунд до выполнения кода. Тем не менее порядок тот же: сначала вся программа парсится/компилируется, потом начинается выполнение.

Смотри тему [[two-phases]] — книга доказывает это тремя видами поведения.

@@ term.interpretation.tr
Интерпретация

@@ term.interpretation.def
Обработка исходного кода строка за строкой: каждая строка преобразуется и сразу выполняется, затем идёт следующая.

JS долго считался «интерпретируемым скриптовым языком», но поведение современных движков этому не соответствует: даже если синтаксическая ошибка стоит в конце программы, первая строка так и не выполняется.

@@ term.tokenizing.tr
Токенизация / лексический анализ

@@ term.tokenizing.def
Первый этап компиляции: поток символов делится на осмысленные для языка части — токены.

```
var a = 2;   →   [var] [a] [=] [2] [;]
```

Разница между tokenizing и lexing тонкая: если токен распознаётся без состояния (stateless) — это tokenizing, если при распознавании срабатывают правила разбора с состоянием (stateful) — lexing.

Термин «lexical scope» происходит именно от названия этого этапа ([[lexical-scope]]).

@@ term.ast.tr
Парсинг и абстрактное синтаксическое дерево

@@ term.ast.def
Второй этап: поток токенов превращается во вложенное дерево, описывающее грамматическую структуру программы. Это дерево называется Abstract Syntax Tree (AST).

```
var a = 2;

VariableDeclaration
 ├─ Identifier (a)
 └─ AssignmentExpression
     └─ NumericLiteral (2)
```

Практическая польза: ESLint, Prettier, Babel, TypeScript и Vite — все читают и изменяют код именно на уровне AST. Ответ на вопрос «почему мой код исправился именно так» обычно лежит в AST.

@@ term.code-generation.tr
Генерация кода

@@ term.code-generation.def
Третий этап: AST превращается в исполняемые инструкции. Для `var a = 2;` движок строит инструкции, которые создают переменную `a` (выделяют память) и записывают в неё значение.

Детали этого этапа сильно зависят от языка и платформы; книга намеренно в них не углубляется и сосредоточена на наблюдаемом поведении.

@@ term.jit.tr
Компиляция во время выполнения

@@ term.jit.def
У JS-движка нет запаса времени: компиляция происходит не на шаге сборки, а за несколько микросекунд до выполнения. Чтобы сохранить скорость, движок использует хитрости — компилирует функции лениво (lazy), а часто выполняемый «горячий» код перекомпилирует и оптимизирует.

Именно поэтому одна и та же функция твоего кода может работать с разной скоростью в разные моменты работы программы.

@@ term.two-phases.tr
Два этапа: сначала парсинг, потом выполнение

@@ term.two-phases.def
Центральное утверждение книги: JS-программа обрабатывается как минимум в два этапа — сначала полный парсинг/компиляция, затем выполнение.

Спецификация не требует слова «компиляция», но требуемое ею поведение возможно только при такой модели. Доказательство — три наблюдения: [[syntax-error]], [[early-error]] и [[hoisting]].

Практический вывод: структура [[scope]] определяется ДО выполнения и не зависит от условий работы.
