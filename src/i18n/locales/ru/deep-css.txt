@@ deep.css.0
Три механизма делают CSS «лёгким в изучении, но трудным в освоении»: box model, каскад и специфичность. Ответ на вопрос, почему страница выглядит не так, как ты ожидаешь, почти всегда в одном из них.

## Box model

Каждый элемент — прямоугольная коробка: content → padding → border → margin. В режиме по умолчанию `content-box` свойство `width` относится только к содержимому, а padding и border добавляются снаружи — поэтому элемент шириной 300px с padding 20px на деле имеет ширину 340px. Современный код меняет это глобально:

```css
*, *::before, *::after { box-sizing: border-box; }
```

Теперь `width: 300px` означает итоговую ширину, и расчёты раскладки упрощаются.

## Схлопывание margin

Вертикальные margin объединяются: нижний margin 20px рядом с верхним 30px даёт 30px, а не 50px. Это происходит и между родителем и потомком и часто вызывает вопрос «почему отступ вылез наружу». Во flex- и grid-контейнерах такого поведения нет вообще — ещё одна причина использовать `gap` в современной раскладке.

## Специфичность

Какое правило победит, определяет вес:

```
inline style        1,0,0,0
#id                 0,1,0,0
.class, [attr], :hover  0,0,1,0
element, ::before   0,0,0,1
```

Сравнение идёт слева направо: один `#id` сильнее любого количества `.class`. При равном весе побеждает то, что написано последним, — это правило [[cascade]].

`!important` ломает эту систему и начинает войну: один `!important` перебивается только другим `!important`. В реальных проектах его используют лишь в случаях вроде перебивания inline-стиля сторонней библиотеки.

## Каскадные слои

[[cascade-layer]] решает эту проблему на уровне структуры. Порядок слоёв важнее специфичности:

```css
@layer reset, vendor, components, utilities;
@layer components { .btn { padding: 8px 16px; } }
@layer utilities  { .p-0 { padding: 0; } }   /* побеждает, даже при меньшей специфичности */
```

## Наследование

[[inheritance]] работает только для части свойств: `color`, `font-*`, `line-height`, `visibility` наследуются; `padding`, `border`, `background` — нет. Ключевые слова `inherit`, `initial`, `unset` позволяют управлять поведением явно.

## Практический вывод

Для стабильного CSS достаточно трёх правил: (1) держи селекторы плоскими и с низким весом (в основном один класс), (2) избегай глобальных селекторов по элементам, (3) храни стили компонента в его собственном файле — CSS Modules, Tailwind или CSS-in-JS, неважно, принцип один: область действия стиля должна быть ограничена.

## Понятие двух осей

[[main-axis]] задаётся через `flex-direction`. Это самая путаемая часть: при `row` `justify-content` работает по горизонтали, а `align-items` — по вертикали; при `column` они меняются местами.

```css
.toolbar{
  display: flex;
  flex-direction: row;
  justify-content: space-between; /* распределение по главной оси */
  align-items: center;            /* выравнивание по поперечной оси */
  gap: 12px;                      /* вместо margin — нет проблемы схлопывания */
  flex-wrap: wrap;                /* на узком экране переносить на следующую строку */
}
```

## Расшифровка свойства flex

`flex: 1` на самом деле означает `flex: 1 1 0%`: расти, сжимайся, начальный размер ноль. `flex: 1 1 auto` начинает с размера содержимого — результаты разные. [[flex-grow]] делит свободное место долями, а `flex-shrink` управляет сжатием.

Типичный пример двухколоночной раскладки:

```css
.sidebar { flex: 0 0 280px; }   /* фиксированный: не растёт и не сжимается */
.content { flex: 1 1 auto; min-width: 0; }
```

## Ловушка min-width: 0

Значение `min-width` у flex-элемента по умолчанию — `auto`, то есть он не может сжаться меньше своего содержимого. Если длинный текст или `overflow: hidden` работают не так, как ожидается, причина почти всегда в этом. Решение — написать `min-width: 0`. Эта одна строка решает бесчисленные проблемы раскладки, и о ней спрашивают на собеседованиях.

## Тонкости выравнивания

`align-items` относится ко всем элементам, `align-self` — к одному. А `margin-left: auto` — самый короткий способ оттолкнуть один элемент вправо; классический приём для группы кнопок в правой части тулбара.

```css
.actions { margin-left: auto; }
```

## Flex или Grid

Совет простой: если содержимое диктует свой размер и ось одна — Flex; если ты заранее делишь область на колонки и строки — [[css-grid]]. Они не заменяют друг друга, а используются вложенно: страница — Grid, внутренности карточки — Flex.

@@ deep.css.2
[[css-grid]] — единственная система раскладки, работающая сразу по двум осям, и она предназначена для структуры страницы. Отличие от flexbox: в Grid область заранее делишь ты, а содержимое в неё размещается.

## Задание колонок

```css
.layout{
  display: grid;
  grid-template-columns: 280px minmax(0, 1fr);  /* сайдбар + содержимое */
  gap: 24px;
}
```

[[fr-unit]] обозначает долю оставшегося свободного места. Важно привыкнуть писать `minmax(0, 1fr)`: при простом `1fr` колонка не может сжаться меньше содержимого, и широкая таблица разваливает раскладку — это Grid-версия проблемы `min-width: 0` из flexbox.

## Адаптивность без media query

Самый используемый приём Grid:

```css
.cards{
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(260px, 1fr));
  gap: 16px;
}
```

Число колонок меняется автоматически в зависимости от ширины контейнера. `auto-fill` сохраняет место под пустые колонки, а `auto-fit` схлопывает пустые колонки и растягивает имеющиеся элементы — разница видна, когда элементов мало.

## Именованные области

Чтобы читаемо описать сложную схему страницы:

```css
.page{
  display: grid;
  grid-template-areas:
    'header header'
    'nav    main'
    'footer footer';
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  min-height: 100dvh;
}
.page > header { grid-area: header; }
.page > nav    { grid-area: nav; }
```

Для мобильной версии достаточно заново расставить те же области в одну колонку — не трогая HTML.

## Объединение строк и колонок

```css
.wide { grid-column: span 2; }      /* занимает две колонки */
.full { grid-column: 1 / -1; }      /* всю ширину от края до края */
```

Современные браузеры поддерживают `subgrid`: дочерняя сетка наследует линии родителя. Это решает проблему выравнивания заголовка, текста и кнопки в ряду карточек — раньше для этого задавали фиксированную высоту.

[[responsive]] дизайн — это не отдельный сайт для каждого типа экрана, а подстройка одного и того же содержимого под доступное пространство. В современном CSS потребность в media query заметно сократилась.

## Логика mobile-first

В подходе [[mobile-first]] базовый стиль пишется для узкого экрана, а затем расширяется через `min-width`:

```css
.grid { display: grid; gap: 16px; }                 /* мобильная версия: одна колонка */
@media (min-width: 720px){
  .grid { grid-template-columns: 1fr 1fr; }
}
```

Причина проста: мобильная раскладка всегда проще, поэтому, если взять её за основу, придётся писать меньше правил и меньше переопределений.

## Выбор breakpoint

Значения [[breakpoint-css]] не выбирают по моделям устройств. Правильный способ: медленно сужай окно и ставь контрольную точку там, где раскладка действительно ломается. Обычно хватает 3–4 точек.

## Плавные размеры

Функция [[clamp]] подстраивает размер на промежуточных экранах без отдельных правил:

```css
h1 { font-size: clamp(1.75rem, 1.2rem + 2.5vw, 3.25rem); }
.section { padding-block: clamp(40px, 6vw, 88px); }
```

Важно, чтобы в среднем выражении была часть в `rem`: чистый `vw` ломает настройку размера шрифта пользователя и создаёт проблему доступности.

## Единицы viewport

В мобильных браузерах `100vh` из-за адресной строки выходит за пределы страницы. Современное решение: `100dvh` (динамическая), `100svh` (малая), `100lvh` (большая). Для полноэкранных блоков используй `min-height: 100dvh`.

## Изображения и таблицы

Есть два классических источника горизонтальной прокрутки: изображения без ограничения размера и широкие таблицы. Решение:

```css
img, video { max-width: 100%; height: auto; }
.table-wrap { overflow-x: auto; }   /* пусть таблица прокручивается в своём контейнере */
```

## Привычка при проверке

## Custom properties

[[css-variable]] — не обычная переменная препроцессора: она живая в браузере, подчиняется каскаду и может читаться и записываться из JS.

```css
:root{ --accent:#1C6A53; --radius:10px; --space:16px; }
.card{ border-radius: var(--radius); padding: var(--space); }
.card.compact{ --space: 8px; }   /* меняется только в этой ветке */
```

Благодаря этому механизму смена темы сводится к нескольким строкам: достаточно переопределить те же переменные в блоках `@media (prefers-color-scheme: dark)` и `[data-theme='dark']`. Важное правило: единственное определение цвета не должно находиться внутри media-блока, иначе в состоянии по умолчанию значение не найдётся.

## Container queries

[[container-query]] означает адаптивность на уровне компонента. Элемент смотрит не на экран, а на свой контейнер:

```css
.card-host{ container-type: inline-size; }
@container (min-width: 420px){
  .card{ grid-template-columns: 120px 1fr; }
}
```

Значение этого велико: один и тот же компонент карточки в сайдбаре выглядит как одна колонка, а в широкой области — как две, и это поведение остаётся в собственном файле компонента, не завися от раскладки страницы.

## :has() — родительский селектор

[[has-selector]] — возможность, которую ждали много лет:

```css
.field:has(input:invalid){ border-color: crimson; }
.card:has(img){ grid-template-rows: 160px auto; }
form:has(:focus-visible){ box-shadow: 0 0 0 3px var(--accent-soft); }
```

Раньше такое решали добавлением класса через JS.

## Другие полезные новинки

`:is()` и `:where()` сокращают списки селекторов (`:where()` не добавляет специфичности — идеально для стилей библиотек). `aspect-ratio` сохраняет пропорции блоков для изображений и видео. `text-wrap: balance` равномерно делит заголовки на строки. `color-mix()` позволяет создавать производные оттенки из существующего цвета. А `@layer` выстраивает порядок приоритетов в больших кодовых базах ([[cascade-layer]]).

## Поддержка и постепенное улучшение

Перед использованием нового свойства его можно защитить через `@supports`:


Но на практике все свойства из этого списка в 2026 году поддерживаются всеми основными браузерами; в корпоративных проектах с требованием поддержки старых браузеров стратегию `@supports` или полифиллов стоит согласовать заранее.

[[tailwind]] — альтернативная модель написания CSS: вместо того чтобы придумывать имена и держать отдельные файлы, готовые атомарные классы пишутся прямо в разметке. Подход называется [[utility-first]], и нужно понимать как его сильные, так и слабые стороны.

## Почему это работает

```html
<button class='inline-flex items-center gap-2 rounded-lg bg-emerald-700 px-4 py-2 text-sm font-medium text-white hover:bg-emerald-600'>
  Сохранить
</button>
```

Есть три реальных выигрыша: (1) не нужно выдумывать имена, (2) стиль находится рядом с элементом — при удалении не остаётся мёртвого CSS, (3) значения ограничены сами собой, потому что классы берутся из набора токенов в твоей конфигурации. То есть конфигурация Tailwind — это, по сути, твоя система [[design-token]].

## Слабая сторона и правильное решение

Длинные повторяющиеся строки классов ухудшают читаемость. Неправильное решение — заново создавать CSS-классы через `@apply`: это теряет все преимущества Tailwind и возвращает проблему именования. Правильное решение — превратить повторяющийся блок в компонент:

```tsx
function Button({ variant = 'primary', ...props }) {
  const base = 'inline-flex items-center gap-2 rounded-lg px-4 py-2 text-sm font-medium';
  const styles = {
    primary: 'bg-emerald-700 text-white hover:bg-emerald-600',
    ghost: 'border border-slate-300 text-slate-800 hover:bg-slate-50'
  };
  return <button className={`${base} ${styles[variant]}`} {...props} />;
}
```

Для условных классов используют `clsx` или `tailwind-merge`; последний правильно разрешает конфликтующие классы (`p-2` и `p-4`).

## Вместе с готовой UI-библиотекой

Если в одном проекте используются библиотеки вроде DevExtreme или MUI, граница должна быть чёткой: раскладка и собственные компоненты управляются через Tailwind, а внутренний вид компонентов библиотеки — её собственным механизмом тем. Вмешиваться утилитами во внутреннюю DOM-структуру библиотеки — решение, которое ломается при обновлении версии.

## Альтернативы

CSS Modules дают локальную область действия и сохраняют обычный синтаксис CSS — хороший выбор, если команда привыкла к классическому CSS. CSS-in-JS (styled-components, Emotion) из-за затрат во время выполнения отступает в современном React, особенно с серверными компонентами. Решения без рантайма, такие как Vanilla Extract и Panda CSS, набирают популярность в проектах, где хотят типизированный CSS.

> С технической точки зрения выбор нейтрален: важно, чтобы команда придерживалась одного стиля. Смешение трёх разных подходов к стилям в одном проекте — самая дорогая ситуация.

@@ deep.css.6
Анимация в интерфейсе — не украшение, а способ объяснения: она показывает, откуда появился элемент, что изменилось и чего ждать. Избыточная или неправильная анимация создаёт и тормоза, и проблемы доступности.

## transition — переход между состояниями

```css
.btn{
  background: var(--accent);
  transition: background-color .18s ease, transform .18s ease;
}
.btn:hover{ background: var(--accent-ink); transform: translateY(-1px); }
```

[[transition]] работает только между двумя состояниями, и важно явно перечислить, какие свойства анимируются. `transition: all` — скрытая проблема производительности: в анимацию попадают и свойства, которые ты не имел в виду.

## keyframes — многоэтапное движение

```css
@keyframes slide-in{
  from{ opacity: 0; transform: translateY(6px); }
  to  { opacity: 1; transform: none; }
}
.panel{ animation: slide-in .2s ease-out both; }
```

[[keyframes]] нужны для повторяющегося или многоэтапного движения: эффект skeleton-загрузки, привлекающий внимание значок, поэтапное появление.

## Что можно анимировать

Только `transform` и `opacity` работают на слое компоновщика и не затрагивают расчёт раскладки. Анимация `width`, `height`, `top`, `margin` требует [[reflow]] на каждом кадре и вызывает заметное дёрганье на слабых устройствах.

```css
/* плохо */  .box{ transition: width .3s; }
/* хорошо */ .box{ transition: transform .3s; transform: scaleX(1.2); }
```

Когда нужно анимировать высоту, современное решение — переход `grid-template-rows: 0fr → 1fr`; трюк с `max-height` требует приблизительного значения и работает неидеально.

## Время и кривая

Практический диапазон для анимаций интерфейса — 120–250 миллисекунд. Более длинные заставляют пользователя ждать. Для появления естественнее выглядит `ease-out`, для исчезновения — `ease-in`.

## Уважение к движению

Настройка [[prefers-reduced-motion]] — реальная необходимость для пользователей с вестибулярными нарушениями:

```css
@media (prefers-reduced-motion: reduce){
  *, *::before, *::after{
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
  }
}
```

Вместо полного отключения можно дать более мягкий вариант: отменить перемещение, но оставить переход по `opacity`.

## В контексте React

Когда элемент удаляется из списка, для анимации исчезновения его нужно какое-то время держать в DOM — для этого используют библиотеки вроде Framer Motion. В простых случаях хватает CSS, и загружать дополнительный пакет с точки зрения [[bundle-size]] неоправданно.
